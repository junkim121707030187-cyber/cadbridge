# 개발 절차 제안
관련: [AGENTS](../AGENTS.md), [작업 보드](TASK_BOARD.md), [검증](VALIDATION.md)

사용자가 URL을 지정한 비공개 [cadbridge 저장소](https://github.com/junkim121707030187-cyber/cadbridge)의 main에 준비한 정본을 반영했다. 실제 commit·파일 대조·문서 검사 결과는 [상태·근거](STATUS_AND_EVIDENCE.md)를 따른다. 후속 변경의 협업 승인 정책은 미정이다. 확인한 대상과 기존 규칙을 우선하며 아래 기준을 검토해 적용한다.

1. 작업 시작: 요구 ID와 작업 완료 조건, 변경 대상, 입력 출처·권리, 기준 버전, 미커밋 변경을 확인한다.
2. 작은 작업: 한 관문 또는 한 실패 경로를 다루는 변경으로 나누고 입력/출력 계약과 실패 처리를 먼저 적는다.
3. 작업본 분리: 원본 소스·benchmark·설계 맥락·전체 증거 archive를 보존한다. 생성물과 로그는 작업별 경로로 분리하고 필요한 증거만 정리해 추적한다.
4. 검증: 문서/모듈/어댑터/native 통합 등 변경 범위에 맞는 검사를 수행한다. 미실행·mock·수동 개입을 표시한다.
5. 기록: 요구·구현·검증 간 연결, 실패와 제약, 결정 근거를 갱신한다. 검증 안 된 작업본을 완료 버전으로 표시하지 않는다.
6. 복구·인계: 실패 결과는 유효 버전으로 승격하지 않는다. 복구 지점과 재현 절차·미해결을 남긴다. 기존 사용자 변경을 강제 reset하지 않는다.

## Git 기준 제안
문서 기준선과 관문별 작은 commit, 작업별 branch, 검토 가능한 diff와 요구 ID 연결을 권장한다. branch 명명·리뷰 인원·병합 권한·CI 기준은 기존 저장소 정책 또는 사용자 협업 결정 후 정한다. 사용자에게 어댑터 함수나 JSON 필드 선택을 요구하지 않는다.

비밀·캐시·가상환경·개인 설정은 [.gitignore](../.gitignore)로 제외한다. benchmark 원본·설계 맥락·선별 증거는 통째로 제외하지 않고 권리·민감정보를 검토해 보존한다. 대형 파일 관리 방식은 저장소가 정해진 뒤 엔지니어가 제안한다. LICENSE는 소유자 결정 전 부여하지 않는다.
