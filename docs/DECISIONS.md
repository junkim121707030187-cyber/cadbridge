## 2026-11-23 · 저장소 줄바꿈 정책 (D-12)
- 합의(사용자 결정): Git이 줄바꿈을 변환하지 않고 바이트 그대로 저장한다(`.gitattributes`의 `* -text`). 이 저장소는 파일 SHA256으로 무결성을 검증하므로, 커밋 시 Git이 바이트를 바꾸면 기록된 해시와 실제 파일이 어긋난다. 새로 만들거나 고치는 텍스트 파일의 LF는 `.editorconfig`로 유도한다.
- 대체: 기존 `* text=auto`와 확장자별 `text eol=lf` 규칙을 대체한다. 이미 커밋된 파일의 바이트는 바꾸지 않는다.
- 근거: 임시 clone에서 기존 규칙으로 CRLF 파일을 stage하면 Git이 LF로 바꿔 작업 폴더와 다른 해시로 저장함을 확인했다. `* -text`에서는 기존 tracked 파일이 커밋과 바이트 일치하고 M 표시가 사라졌다. 결과는 [상태·근거](STATUS_AND_EVIDENCE.md)를 따른다.
- 순서 합의: 줄바꿈 정책 → 매니페스트 크기 필드명 `size_bytes` 통일 → (선택) 루트 문서 LF 변환 → (선택) CRLF 검사 → 구조 정리. 커밋 하나에 목적 하나를 둔다.
- Git 작업 합의: 커밋·push는 사용자가 직접 한다. 에이전트는 변경과 커밋 메시지 제안까지만 한다.
- 미정: 시제품 앱이 Windows에서 일부 JSON을 CRLF로 쓰는 문제(`prototype/app/prototype.py`의 `write()` 등)의 수정 여부. 앱 코드 변경은 이번 범위 밖이다.
