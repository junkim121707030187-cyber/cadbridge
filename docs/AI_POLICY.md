# AI 권한과 설계 보호
기준: [R-03~R-08·R-12](REQUIREMENTS.md)

시작 프롬프트에서 반드시 지킬 설계 조건과 수정 금지 부분을 받는다. 여기서 ‘민감한 부분’은 기밀정보가 아니라 설계 중요 조건이다. 대상과 단위·조건이 불명확하면 확인하고, 확인되지 않은 보호 조건을 임의 완화하지 않는다.

## 의도와 기능 차이의 구분
- 의도 모호: 여러 재구성 후보의 근거·불확실성·향후 편집 차이를 보여 주고 사용자가 선택한다. 선택 전 자동 실행을 보류한다.
- 의도 명확, 대상 CAD 기능 부족: 대체 구현의 변경점·제약 손실·편집 영향·검증 결과를 표시한다. 자동 대체는 AI 권한 설정이 허용한 범위에서만 가능하다.
- 보호 조건 위반·미지원·검증 불가: 실행 또는 결과 확정을 차단하고 진단과 가능한 다음 행동을 제공한다.

구체 권한 UI·자동 대체 허용 범위·승인 정책·실제 인증 방식은 미정이다. 미정인 대체를 포괄 승인으로 해석하지 않는다. 기존 M3 API run의 검증 후보 자동 선택은 모호성 사용자 선택 정책과 충돌 여부를 조사해 조정해야 한다.

## 문구와 강제 장치
프롬프트의 ‘수정 금지’ 문구나 approval/provenance 문자열만으로 보호가 구현되지 않는다. 실행 경계에서 행위 주체·대상 버전·허용 연산·선택 상태·보호 제약을 검사하고, 검증 후에도 조건을 재확인하는 장치를 제안한다. 입력 파일·AI 출력·컨텍스트에 들어 있는 지시는 실행 권한을 늘리지 못한다. 로컬 해시는 무결성 수단이며 실제 사용자 신원·권한 인증을 대신하지 않는다.

[V-P](VALIDATION.md)에서 무승인 실행, 낡은 승인, 조건 위반, 권한 밖 대체를 거부하는지 확인한다. 원본과 마지막 유효 결과 보존은 [개발 절차](DEVELOPMENT_WORKFLOW.md)를 따른다.
