# 데이터와 AI 작업 컨텍스트
기준: [R-07·R-08](REQUIREMENTS.md), [AI 정책](AI_POLICY.md)

프로젝트는 요구와 전체 맥락을, 부품은 개별 설계 대상을, 설계버전은 해당 시점의 모델과 이전 버전 관계를 가진다. AI 작업은 입력 설계버전·사용 컨텍스트·후보·선택·출력 설계버전을 연결한다. 프로젝트 맥락은 참고하되 작업 시 실제 사용한 범위와 버전을 고정해 둔다. 후속 조립체 관계는 별도 설계한다.

| 정보 종류 | 예 | 기록 원칙 |
|---|---|---|
| 원본 확인 | native에서 직접 읽은 치수·제약 | 파일·버전·읽기 경로와 확인 한계 |
| 기하 측정 | STEP 홀 지름 측정 | 단위·측정법·오차·대상 면 참조 |
| 사용자 요구 | 홀 위치 고정, 두께만 변경 | 명시 조건·대상·변경 이력 |
| AI 가정 | 대칭 배치가 의도일 가능성 | 가정 표시·근거·대안·사용자 선택 |

## 최소 보존 항목 제안
프로젝트·부품·버전·작업의 안정적인 식별자와 연결, 원본 위치·해시·형식·단위, CAD 및 도구 버전, 시작 프롬프트에서 추출한 보호 조건, 사용 컨텍스트의 출처·버전·범위, 관측·측정·요구·가정 구분, 후보와 사용자에게 제시한 근거, 선택·대체·실행 승인 범위, 생성 결과와 검증 판정·실패 증거를 보존한다. 시간·행위 주체는 추적 정보이며 인증 여부를 별도로 표시한다.

예: 프로젝트 P의 부품 B 버전 v1을 입력한 작업 W가 ‘두께 변경, 홀 위치 유지’ 요구와 측정 결과를 사용해 후보 C를 만들고, 선택 후 v2 및 검증 증거 E를 연결한다. P/B/v1/W/C/v2/E는 설명용 이름이며 규범 스키마·JSON 필드·API 계약이 아니다.

원시 대화 전체나 비공개 내부 추론을 저장하지 않는다. 사용자에게 설명 가능한 근거·판정 요약을 보존한다. 비밀 키는 모델 컨텍스트·로그·Git에서 제외한다. 컨텍스트 보존 기간·삭제·접근 제어·공유 정책은 미정이다. 해당 정책이 없으면 다인 공유를 자동 허용하지 않는다. 컨텍스트 손실·연결 불일치는 [V-C](VALIDATION.md) 실패로 처리한다.
