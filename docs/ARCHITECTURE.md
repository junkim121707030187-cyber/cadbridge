# 구조 제안
[요구사항](REQUIREMENTS.md) 구현을 위한 책임 분리 초안이다. 언어·프레임워크·IR 스키마·솔버·저장소·어댑터 API는 모두 제안이며 미선정이다. M3 코드가 이 구조로 이식됐다는 뜻이 아니다.

| 모듈 | 책임 | 금지·실패 처리 |
|---|---|---|
| 입력 리더 | STEP 및 후속 native 입력의 단위·형상·지원 범위 관측, 원본 참조 보존 | native 정보 없는 STEP에서 이력 사실을 만들어내지 않음; 손상·미지원 거부 |
| 공통 표현(IR) | 기하·피처 후보·제약·출처·불확실성을 프로그램 독립적으로 연결 | 단위·참조·연산 검증 실패 시 계획 전달 중단 |
| AI 계획 | 컨텍스트로 재구성 후보·근거·편집 차이·대체 제안 생성 | 실행 권한 없음; 모호성은 사용자 선택으로 반환 |
| 솔버 | 지원 제약의 일관성·자유도·해 후보 계산 | 불능·과구속·미지원·잔차 초과를 구분 |
| 검증기 | 형상·의도·보호 조건·권한·컨텍스트 판정 | 불합격 결과를 유효 버전으로 승격하지 않음 |
| native 어댑터 | 대상 CAD의 피처·스케치·제약 생성과 저장·재열기·편집·재계산 | 형상 덩어리만 생성한 결과를 native 성공으로 표시하지 않음 |
| 컨텍스트 저장 | 프로젝트·부품·설계버전·AI 작업·승인·증거 연결 | 부분 저장 실패를 성공으로 표시하지 않고 원본·유효 버전 보존 |

## 최소 흐름
입력 및 시작 조건 → 관측과 출처 분류 → IR 검사 → AI 후보 → 모호성 선택/대체 권한 확인 → 솔버 → 임시 native 생성 → 검증 → 저장·종료·재열기·편집·재계산 → 결과와 컨텍스트 확정.

실행 직전과 결과 확정 직전에 같은 대상 버전·보호 조건·승인 범위를 재확인한다. 사용자 선택이나 입력이 바뀌면 낡은 후보와 승인을 재사용하지 않는다. 검증 실패는 진단과 후보로 되돌리고 무한 교정하지 않는다. 재시도·비용 상한은 미정이며 상한 미설정으로 무제한 실행을 허용하지 않는다.

어댑터 경계는 지원 기능 조회, 생성 계획 적용, 저장, 재열기, 편집, 재계산, 결과 관측을 제공하는 방향을 제안한다. 실제 함수명·형식은 프로그램 공식자료 조사와 수동 관문 후 엔지니어가 정한다. 실패 증거·입력 해시·도구 버전·오류 단계는 [검증 계획](VALIDATION.md)에 연결한다.
