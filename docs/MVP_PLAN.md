## 제품 완료와 첫 코드의 관계
제품 MVP 목표는 서로 다른 오픈소스 CAD A의 부품을 B에서 받아 수정·저장하는 것이다. 이번 첫 구현 0.1은 그 선행 native 관문을 닫는 슬라이스다. 명시된 계획을 받아 STEP 형상을 대조하고 FreeCAD에서 Sketcher/PartDesign 부품을 생성·저장·재열기·편집한다. 입력은 알려진 계획 예제군이며 STEP-only 의도 추론이나 외부 LLM 호출은 아직 없다. 첫 코드 성공을 전체 MVP 완료라고 부르지 않는다.

## 출처와 현재 판단
채팅의 최신 요구, Git main fe42a66e8bcbb88566f2ff482cbaecb9bea4d784, Obsidian의 'CADBridge 팀 인수인계와 구현 결과.md' 및 복사본을 읽었다. 과거 M3 시험·제한·외부 API 미실행은 보고된 과거 정보로 보존한다. 현재 Git은 최신 준비 정본이며 Obsidian의 10월 native 보류를 최신 작업 권한으로 재사용하지 않는다. 읽은 문서·해시와 공식자료는 [출처 기록](MVP_SOURCES.md)에 정리한다.

FreeCAD1.0.0을 현재 설치 환경의 기술검증 대상으로 선택한다. 향후 두 CAD 후보는 SolveSpace(A)→STEP→FreeCAD(B)이다. SolveSpace 공식 CLI/STEP 내보내기 지원이 native 생성 API와 같지는 않으며 설치·수동 예제·실제 이전 시험을 별도로 통과해야 한다. CAD쌍을 제품 최종 선정하거나 G0 전체/G2를 통과했다고 주장하지 않는다.

## 검증과 정지 조건
순수 단위 시험, 실제 FreeCAD 실행, GitHub 기본 CI를 구분한다. FreeCAD가 없는 CI에서 native 시험을 건너뛴 상태를 native 통과로 쓰지 않는다. 기술검증용 부피 허용치 1e-5 mm³는 이 예제군 탐색 기준이며 최종 제품 공차가 아니다. product_acceptance는 not_assessed다. 형상 불일치·선택 불일치·보호 위반·기존 출력·원본 변화·미지원 모델·타임아웃에서 중단한다. 실패로 이전 유효 프로젝트를 덮어쓰지 않는다.
