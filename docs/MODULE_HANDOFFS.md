# AI·UIUX·CAD 기계 제약의 분담 인수인계
2026-11-16 · 문서·계약·참고 코드 분리, 신규 런타임 구현·CAD/API 실행 없음.

사용자는 AI 연결의 맥락과 고민 전체를 전담자가 인수할 수 있게 분리하고, 이어 UIUX 사용자 요구와 CAD·기계 특성상 강제할 제약도 별도 모듈로 만들도록 요청했다.

| 논리 파트 | 내려받을 묶음 | 담당 범위 |

| AI_CONNECTOR | [AI 연결](../handoffs/2026-11-16/ai-connection.zip) | 공급자·모델·인증·맥락 요청·구조화 후보·오류·호출 증거; M3 원문 참고 코드 23파일 포함 |
| UIUX_REQUIREMENTS | [UIUX 사용자 요구](../handoffs/2026-11-16/uiux-requirements.zip) | 시작 조건·후보 비교·사용자 선택·대체 공개·검증 상태·저장·복구·맥락 조회 |
| DESIGN_GUARDS | [CAD·기계 강제 제약](../handoffs/2026-11-16/cad-mechanical-constraints.zip) | 비AI 검사·보호 규칙·허용 대체·실제 검증·같은 버전의 선택/저장·원본 보존 |

각 ZIP의 README와 HANDOFF_MESSAGE부터 읽는다. 모듈 안에 책임·입출력 초안·합의·미결정·담당자의 첫 작업·인수 기준·설명용 JSON이 있다. [파일 해시](../handoffs/2026-11-16/manifest.json)로 전달본을 식별한다. AI 참고 코드는 원문 선별본이며 일부 CAD 의존성이 제외돼 독립 실행 패키지가 아니다.

## 후속 사용자 합의
기존 준비 문서의 미정 표 이후 사용자가 FreeCAD 1.1.4와 SALOME SHAPER 9.16.0, CB-P01 부품·공차를 채택하고 구현 착수를 요청했다. 이 절은 이번 인수인계의 최신 기준이다.

- STEP→FreeCAD native부터, 이후 FreeCAD→SHAPER native의 설계 맥락·제약 이전.
- 개별 부품, 한 방향 전달 후 수정·저장이 첫 장면. 조립체·다인 workspace는 후속.
- CB-P01 판100×80×10 mm, 중앙 포켓30×20·깊이5, 관통홀4×Ø8@(±30,±20). 동일 직경·대칭·관통·윗면 기준 깊이를 유지.
- 주요 치수·위치·표면 샘플 거리≤0.01 mm, 입력 내부 공차 선행 기준≤0.002 mm. 상대 대칭차부피1e-6은 진단용, 제조 공차는 미지정.
- 의도가 모호하면 후보·근거·편집 차이를 보여 사용자 선택. 기능 대체는 허용 설정에 따르고 변경을 표시.
- 사용한 맥락·근거·선택·대체·검증 요약을 작업물과 연결한다. 원시 대화·비공개 내부 추론 보관 요구는 아님.
- 숫자는 현재 CB-P01 정책이다. 권한 있는 명시적 새 요구·범위·이유·정책 버전으로 변경할 수 있으나 AI의 사후 자동 완화로 실패를 통과시키지 않는다.

CAD의 고정 계획 생성·저장·완전 종료·새 프로세스 재열기·구동 치수 변경은 LLM 없이 진행할 수 있다. AI 연결은 별도 전담 작업이며 이 native 관문의 선행 의존성이 아니다.

## 역할 사이의 연결
UIUX는 요구와 선택 의도를 전달한다. AI는 미승인 후보를 반환한다. DESIGN_GUARDS·IR·검증은 허용 범위와 실제 조건을 검사한다. 호스트는 같은 입력·정책 버전의 유효한 선택·허용 상태를 확인하고 CAD 어댑터를 실행한다. 저장은 원본·마지막 유효 상태를 보존하며 UI는 검증 범위를 구분해 표시한다.

화면 체크나 AI의 approval 문자열은 신원·권한·검증 성공의 증거가 아니다. 기하 합격을 강도·피로·제조성·규정 적합성의 승인으로 확대하지 않는다. 구체 배포·권한 UI·운영·유지보수·기계 해석 범위는 별도 결정이다.

## 검토 범위
세 묶음에서 UTF-8·JSON·내부 링크·파일 해시·ZIP 무결성을 검사했다. AI 참고 23파일은 원 M3 ZIP 대비 바이트·해시를 확인했다. 새 모듈 실행·외부 모델 호출·CAD 실행은 이 인수인계 작업에서 하지 않았다. 기존 M3의 과거 329/87 시험과 이번 문서 검토를 합산하지 않는다.

관련 요구는 R-03~R-12이며 실제 검증 연결은 각 묶음과 기존 검증 문서를 따른다. [작업 카드](tasks/CB-002.md).
