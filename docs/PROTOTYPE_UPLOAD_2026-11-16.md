# 통합 시제품 GitHub 업로드 인계 · 2026-11-16

## 범위와 요구 연결

사용자가 지금까지 작성한 코드와 AI 예제를 기존 비공개 저장소에 올리고 각 PC에서 확인하도록 요청했습니다. 이어 ‘실행 확인은 나중에, 일단 업로드’로 우선순위를 지정했습니다. 이번 작업은 배포용 복사본·진입 안내와 업로드이며 앱 기능을 추가하거나 다른 PC 실행을 시험하지 않았습니다.

- R-01: `prototype/app/cadbridge`에 native 재구성·편집 구현과 저장 결과가 있습니다.
- R-04, R-09: 조건 검사·실패 시 마지막 유효 버전 보존 구현과 기존 개발 PC 검사 기록을 보존했습니다.
- R-07, R-08: 관측·사용자 조건·AI 응답·버전 결과를 예제에 연결했습니다.
- R-10, R-11: 소프트웨어 검사·기하 검증·최종 제품 합격을 구분합니다. 범용 성능과 서로 다른 두 CAD 이전은 이번 업로드로 검증되지 않습니다.

## 수정 파일과 근거

`prototype/`는 현재 로컬 통합 앱·워크스페이스·검사 코드·출처·실제 예제의 복사본입니다. 실제 AI 입력·응답, v001/v002 native·STEP·검사 결과, 실행 메타데이터를 `prototype/examples/AI_EXAMPLE.md`에서 찾습니다. `deliverables/`에 DOCX와 배포 ZIP을 넣었습니다. 소스·대용량 실행 환경을 구분했고, 계정·토큰·Codex 로그인 설정·원문 대화·비공개 내부 추론은 업로드하지 않습니다.

개발 PC의 절대 경로가 담긴 배포용 JSON·문서는 상대적 표시로 치환했습니다. 원본 로컬 증거는 수정하지 않았으며 배포 파일의 해시는 `BUNDLE_MANIFEST.json`에 별도로 기록합니다. 배포 ZIP도 GitHub에 올린 복사본에서 작성합니다.

## 기존 검사와 이번 미실행 항목

기존 개발 PC에서 관측→Terra→재구성, 치수 편집, FreeCAD 재열기와 워크스페이스 댓글·파일·버전 흐름을 확인했습니다. 소프트웨어 검사 기록은 65개 함수·하위 사례 194개이며 실제 CAD 실행 횟수와 다릅니다. 세부 기록은 `prototype/evidence/`입니다.

**이번 업로드에서는 설치·앱·CAD·AI 실행 검사를 재수행하지 않았습니다.** 다른 PC 설치, 다른 Windows 환경, 새 AI 인증, macOS/Linux 실행은 미검증입니다. 원격 업로드의 파일 목록·해시 대조는 실행 시험과 별개입니다.

## 다음 행동과 복구

팀원은 저장소 ZIP을 내려받아 `prototype/README.md`를 따릅니다. 각 PC에 Python3.11 이상과 `Setup.ps1` 설치가 필요하고, 새 Terra 실행은 개인 Codex 로그인·모델 접근 권한이 필요합니다. 로컬 단일 사용자 구조로 파일·대화는 PC마다 따로 저장됩니다. 다음 작업은 팀원 PC에서 첫 설치·예제 열기·버전 전환을 확인하고 결과를 기록하는 것입니다.

기존 저장소 파일과 앞선 native 구현 PR은 삭제하지 않았습니다. 업로드 전 main은 `fe42a66e8bcbb88566f2ff482cbaecb9bea4d784`입니다. 문제가 있으면 업로드 커밋을 정상 revert하고 이전 기준선으로 돌아갑니다. 강제 초기화·기존 PR 자동 병합은 수행하지 않습니다.
