# 모듈 경계와 계약 준비
[구조 제안](ARCHITECTURE.md), [데이터·컨텍스트](DATA_AND_CONTEXT.md)를 구현으로 옮길 때의 계약 목록이다. 현재는 모두 설계 제안이며 규범 JSON 스키마·어댑터 함수는 미정이다.

| 경계 | 생산→소비 | 정해야 할 내용 |
|---|---|---|
| I-01 | 리더→공통 표현 | 입력 해시·단위·좌표·관측 출처·미지원 |
| I-02 | 공통 표현/맥락→AI 계획 | 보호 조건·가정 구분·후보·대체·불확실성 |
| I-03 | 후보/선택→솔버 | 선택 버전·허용 연산·제약·잔차·불능 사유 |
| I-04 | 검증된 계획→native 어댑터 | 지원 기능·생성·저장·재열기·편집·재계산 결과 |
| I-05 | 실행/검증→컨텍스트 저장 | 작업·버전·승인 참조·검증 증거·확정/실패 상태 |

계약 변경 제안에는 ID·변경 이유·영향 요구·소비자·단위·오류·버전 호환·이행 방법·검사를 적는다. 승인 주체는 실제 저장소 정책과 제품 결정에 맞춰 정한다. 기술 필드·함수·시험 구현은 엔지니어가 준비한다.

MVP0.1 구현의 제한 계약은 [MVP_EXECUTION_CONTRACT](MVP_EXECUTION_CONTRACT.md)에 고정했다. 위 일반 제품 경계 전체가 구현됐다는 뜻은 아니다. plan v1과 worker 요청/보고서, session v1은 이 첫 코드에서 사용한다.
