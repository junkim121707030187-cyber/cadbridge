# 에이전트 작업·검토·인계
관련: [AGENTS](../AGENTS.md), [CONTRIBUTING](../CONTRIBUTING.md), [작업 보드](TASK_BOARD.md)

## 역할
| 역할 | 책임 | 경계 |
|---|---|---|
| 총괄·통합 | 요구 분해, 작업 배정, 경로 충돌 확인, 계약·증거 통합 | 제품 결정을 임의 확정하지 않음 |
| 작업자 | 배정 범위 수정, 검사, 차이와 실패·인계 기록 | 다른 작업자 변경·원격 권한을 넘지 않음 |
| 검토자 | 요구·diff·증거·회귀·정책 확인 | 자기검토와 독립 검토를 구분; 미실행을 통과 처리하지 않음 |

한 명/한 에이전트가 순차로 역할을 수행해도 된다. 독립 검토자가 없다면 ‘자기검토만 수행’이라고 기록한다. 특정 AI 공급자·유료 API·자동 오케스트레이터는 선택하지 않았다.

## 작업 카드와 상태
[작업 카드](tasks/README.md)에 ID, 요구 ID, 목표·비범위, 의존성, 기준 commit/입력 해시, owner, 수정 허용 경로, 완료조건·검사, 인계·검토를 남긴다.

`ready → claimed → working → review → done`을 쓴다. 막히면 `blocked`와 사유·재개 조건을 남긴다. `done`은 명시한 완료조건과 증거에만 적용한다. 카드 담당 표시는 실제 동시성 잠금이나 인증 수단이 아니다. 여러 에이전트가 같은 카드를 동시에 claim하지 않도록 총괄이 배정을 직렬화한다.

## 병렬 작업
독립 조사·검토와 파일 경계가 나뉜 작업을 병렬로 한다. 서로 의존하는 수정은 선행 결과를 확인한 뒤 진행한다. 공용 파일은 한 명만 쓰고 다른 작업자는 제안·패치를 전달한다. worktree를 쓰면 branch·기준 commit·작업 폴더를 카드에 기록한다. 공유 폴더에서 동시 작업할 때는 서로 다른 파일에 한정하며 저장 직전 타인의 변경을 확인한다.

## 계약 변경
[계약 목록](INTERFACES.md)에 영향 모듈·형식·단위·실패 처리·버전·호환성·검사와 미정을 기록한다. 데이터 예시를 규범 스키마로 몰래 승격하지 않는다. 계약이 바뀌면 소비 모듈의 작업 카드도 갱신한다.

## 새 대화·다른 클라우드로 넘길 때
전달 단위는 접근 가능한 Git 저장소 URL+branch+commit+인계 경로다. 원격 미반영 작업은 diff 또는 복원 가능한 파일 묶음과 SHA256을 제공한다. 한 컨테이너의 로컬 경로만 보내고 다른 환경에서 회수됐다고 주장하지 않는다. 자격증명·원시 대화 전체·비공개 내부 추론은 인계하지 않는다.

## 범위와 권한
최신 요청은 사용자가 지정한 비공개 [cadbridge 저장소](https://github.com/junkim121707030187-cyber/cadbridge)의 main에 준비한 작업 환경·제품 개념도·협업 파일을 업로드하는 것이다. 이전 중단 이후 사용자가 원격 업로드를 다시 지시했다. 현재는 지정 저장소 main 업로드 준비 상태이며 실제 반영·검사·CI 결과는 [상태·근거](STATUS_AND_EVIDENCE.md)를 따른다. CAD 구현·설치·제품 CAD/API 호출·유료 사용은 이 요청에서 시작하지 않는다. 구현 작업, CAD 내부 기능 대체 승인, Git 원격 작업 권한은 각각 구분한다. 문서의 허용 문구만으로 OS·GitHub·CAD 권한이 강제되지 않는다.
